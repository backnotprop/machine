Connect your agent

Your own agent, in the terminal it already runs in, with your login and your repo, draws the machine in the designer. Nothing runs on our server, so it works the same locally and hosted.

How it works

Four pictures. The pattern is the one the Plannotator Inbox uses for the same three hosts.

1 · once, in the terminal Sign in, install the plugin, start the agent

Two lines for the computer, once. Then the agent is started in the repo the machine is about.

2 · the designer sees it The plugin polls, the designer shows the session

The plugin long-polls our server with the login's key. The first poll is the handshake: host, folder, session.

3 · you type, the agent hears it The message becomes a turn in that session

Held on the server until the agent is idle, then entered as a turn, once. Nothing interrupts what it is doing.

4 · it draws The agent calls draft, the graph redraws

The plugin's one tool proxies to our MCP: draft, get_draft, say. The server checks each draft and the stage follows it, exactly as today.

The three hosts

Each one has a native plugin API, so the connection is a real plugin, not a prompt trick. Other agents get the tool over plain MCP today and a wake once the MCP Events spec lands.
