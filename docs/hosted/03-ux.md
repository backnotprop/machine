# Hosted machine: screens and flows

The hosted version is the same product with people in it. One team owns machines, runs, agent keys and credentials; every member sees the same Runs page. Nothing in the local UI is restyled: the bar, the rows, the frame, the ask and the history are reused as they are. What is added is listed per screen below as **new**. The model behind the screens is in `01-teams-and-signin.md` (teams, members, keys, AuthKit) and `02-credentials.md` (the store, slots, the lease); this document uses their names. The mock is `03-ux.html` (sign-in, team, credentials, runs, run).

Vocabulary, in the product's voice:

| Concept | Words |
|---|---|
| The people | **Team** (one WorkOS organization, shown by name); **Owner** manages people and the team, **Member** does the work. Two roles, nothing else. |
| A person joining | **Invitation**: "Michael invited you to Plannotator". WorkOS sends the email. |
| The agent's way in | **Agent key**: one per computer or job (`laptop`, `ci`), shown once, tied to the member who made it. The same key signs the `machine` CLI in. |
| What agents act with | **Credentials**: a **connection** (GitHub App, Linear, by OAuth) or a **token** (pasted). Each has a name the team sees: "GitHub · michael", "npm publish token". |
| What a machine asks for | A **slot**: `credentials: [{ id: "github", provider: "github", why: "open and merge the PR" }]`. A stored credential is **bound** to a slot. An empty slot is **needed**. |
| The record | "Used GitHub · michael for `gh pr create`" is a move in the run's history, like any other. A hand-off ("Handed the npm token to the agent") carries a red Block. |
| Taking one away | **Remove** a credential (its slots go empty); **Revoke** a key; **Remove** a member. |

The one rule that carries over from SPEC.md: the tool, not the model, owns state. A credential is used only inside a running run of a machine that declares the slot, in a state where the slot is live, and every use is written into that run's history.

## Flows

1. **First sign-in.** `app.machine.run` signed out is one page: the mark, one sentence, **Sign in**. Sign in goes to `/auth/login`, which opens the WorkOS AuthKit hosted page (Google, GitHub, email code; nothing of ours). Back from AuthKit, a person with no team sees **Create a team** (`#/teams/new`); a person who arrived through an invitation already has a seat and lands on Runs. Both are one field or nothing, on the sign-in page's surface.
2. **Create a team.** Name. **Create team** makes the WorkOS organization and the owner's seat, and lands on Runs, empty.
3. **Invite.** Team page → Invitations: an email field and **Invite** (owners). The invitation appears under the members as a quiet row until it is accepted. WorkOS sends one link; it ends at the same AuthKit page, then here.
4. **Connect an agent.** Team page → Agent keys → **New key**. The key appears once on a raised surface with the exact `claude mcp add` line and the `machine login` line, ready to copy. Closing it leaves a row: name, prefix, who, created, last used. Runs' empty state links here.
5. **Publish a machine.** The editor as it is, with one more part in the inspector: **Credentials**, the slots the machine declares, "one per line: `id · provider · why`", and under each slot what the team has bound to it ("GitHub · michael", **change**) or **Connect**. The problems footer notes an empty slot; publishing is still allowed, the run will block instead. In hosted mode Publish bumps the version; the Skill pane shows the `claude mcp add … --header` line and a download.
6. **Run.** The agent begins a run through the team's MCP with its key. Preflight checks the slots on the server. If one is empty, the run is created **blocked** with the need "Connect Linear for Triage an issue (`fetch_issue`)" (the existing blocked machinery, nothing new; the need carries the connect link). Otherwise the agent runs `machine run run_x -- gh pr create` and the CLI leases the credential into that one command; or, for an API call, the `request` tool makes it from the server. Either way the run's history gets a "Used …" move.
7. **Team runs.** Every member sees the same Runs page. Needs you is the team's queue: whoever answers, answers.
8. **Run view.** The same page; the agent's line also names the member whose key started it, and the history shows credential use and which member chose or unblocked.
9. **Credentials.** Connect, paste, remove; which machines use which; what is needed and empty.

## Screens

### Sign in (`/`, signed out)

- **On it.** The mark at 44px; the title "machine"; one sentence: "Processes you draw. Agents follow them. A tool keeps them on the rails."; a row of hollow blocks (`EmptyPath`); one primary pill **Sign in**; a hint: "Opens WorkOS. If someone invited you, use the email the invitation came to." Nothing else: no feature grid, no screenshots.
- **Reused.** The `.empty` surface, `EmptyPath`, `Pill`, `.hint`, the page container and the top bar (brand only, no switch while signed out).
- **New.** The page itself, and its follow-up on the same surface: **Create a team** (Name field, the address underneath in mono, **Create team**). An invited person needs no screen; their seat exists when they arrive. The mock also shows a "Michael invited you" surface for the case where an invitee signs in with a different email and is sent back to the right one.

### Team (`#/team`)

- **On it.** `PageHead`: the team name, quiet line "`plannotator` · 4 members · 1 invitation · 2 agent keys", actions: **Invite** (owners; also **Rename**). Then four sections with `SectionHeading`, each a list of rows:
  - **Members.** Row: name, email in ink-3; right: the role as a quiet word ("Owner" / "Member") and, for owners on hover or focus, the quiet links "Make owner" / "Remove". Removing confirms in place ("Remove Dana for good" with a red Block; reverts after 4 s) and revokes her keys. The last owner has no Remove link.
  - **Invitations.** A field and **Invite** on the same line, then pending rows: email, "sent Oct 18 by Michael", quiet links **Resend** · **Revoke**. Accepted invitations become members and leave this list.
  - **Agent keys.** One line of context: "An agent connects over MCP at `https://app.machine.run/mcp` with a key you make here. Runs it starts carry your name. The same key signs the `machine` CLI in, so `machine run` can lease the team's credentials to a command." **New key** opens an inline field (name, default `laptop`) and **Make key**. The key then shows **once** on a raised surface: the key in mono, the `claude mcp add --transport http machine https://app.machine.run/mcp --header "Authorization: Bearer mk_…"` line, the `machine login mk_…` line, **Copy**, and the hint "Shown once. Lose it, make another." Existing keys are rows: name, prefix `mk_live_7Hq2…`, "michael · made Oct 12 · used 3m ago", **Revoke** (in place). Members revoke their own; owners any.
  - **Plan.** One quiet line, the place billing will take: "Free while hosted machine is in preview. Nothing to pay yet." No button.
- **Reused.** `PageHead`, `SectionHeading`, `.rows`/`.row` (no tables), `Pill`, `.link`, `.field`, the in-place confirm from Cancel run, the inset surface for the key block, `Block`.
- **New.** The page, the role word, the invitation row, the key row and the show-once surface.

### Credentials (`#/credentials`)

- **On it.** `PageHead`: "Credentials", quiet line "What agents may act with on Plannotator's behalf · 3 connected · 1 needed", actions: **Connect GitHub**, **Connect Linear**, **Paste a token**. Groups, like Runs:
  - **Needed** (first, only when non-empty): every slot a published machine declares that nothing is bound to. Row with an amber Block in the status column: "Triage an issue needs `linear`" · "Linear · to read the issue and its thread · nothing connected yet" · "One run is blocked until it is." · **Connect Linear** on the right. Connecting from here binds the slot (`?machine=&slot=` on the OAuth start). A pasted token of the right provider binds the same way.
  - **Connected.** Rows with a graphite Block: the credential's name ("GitHub · michael"), one line "Connection · GitHub App as `michael` · repositories plannotator, plannotator-docs · connected Oct 12" or "Token · npm as `plannotator-bot` · pasted by Dana, Oct 15"; under it "Used by Ship a bug fix `github`, Release Plannotator `github`" as links to the machines, with "live only in `publish`" when a state restricts the slot; right: "used 3m ago" and a quiet **Remove**. Remove confirms in place; its slots go empty and show under Needed; runs that used it keep their record. A connection whose refresh failed shows "needs reconnecting" in place of the time and a **Reconnect** pill.
  - **Paste a token** opens inline under the head: Provider (GitHub, npm, AWS, or any HTTP API; the catalog decides the fields), Name, the token field(s), **Save**. The hint: "Checked with `npm whoami` before it is saved. Stored encrypted; agents use it only inside a run of a machine that needs it, and every use is on that run's history." Save runs the provider's verify call and shows the account it found.
  - **Connect GitHub / Linear** leaves for the provider's page (the GitHub App installation, Linear's OAuth) and comes back to this list with the new row, bound to the slot it was started from if any.
- **Reused.** `PageHead`, the grouped `.rows` with eyebrows (`Needs you` becomes `Needed`), `Block` in the 150px status column, `.field`, `Pill`, `.link`, the in-place confirm.
- **New.** The page, the credential row, the paste form, the OAuth round-trip.

### Editor: one more part

- **On it.** In the inspector, after Checks: **Credentials** with the same summary line ("`github`, `npm`" or "None"). Open, it is one textarea, "One per line: `id · provider · why the agent needs it`", and under it one line per slot with what is bound: "`github` · GitHub · michael · change" or "`linear` · Linear · **Connect**". A state's part gains an optional "Credentials live here" line (`npm`) so a token exists only during that state. The skill the agent reads gains a "Credentials" section: the slots, when they are live, and three rules: use `machine run` or the `request` tool; never ask a person for a token; never print one. The problems footer gets a note, not a problem: "`linear` has nothing bound. Runs will block until it does." with a link to Credentials.
- **Reused.** Everything; it is one more `Part`.
- **New.** The field, the bound line and the note.

### Runs (team scope)

- **On it.** Unchanged in shape: Needs you · Running · Finished. Each row's agent line now reads "Claude Code · michael" (the agent, then the member whose key started it). The page's quiet line is the team's: "3 need you · 1 running · 5 finished". A run blocked on an empty slot reads like any blocked row, with the engine's need quoted: "Connect Linear for Triage an issue (`fetch_issue`). Nothing is bound to its `linear` slot." The empty state says: "No runs yet. Connect an agent, publish a machine, then ask the agent to run it." with **Connect an agent** → Team.
- **Reused.** All of `runs.tsx`.
- **New.** The member's name on the row; the empty state's link.

### Run view

- **On it.** Unchanged frame, HUD, ask, history and facts, with:
  - The quiet line under the title: "Your decision at `await_review` for 4m · started 12:03 by Claude Code · michael".
  - **History.** The heading counts uses: "newest first · 4 moves · 1 credential use". A new move, by the agent, in the chapter where it happened: "Used GitHub · michael for `gh pr create`" with the quiet line "Leased to the command on michael's laptop · slot `github` · the token stayed out of the model's context". A server-side call reads "Called GitHub: `POST /repos/…/pulls` → 201". A hand-off reads "■ Handed the npm token to the agent" with a red Block, because the model saw it. Other people's moves are named: "Dana chose `approved` → `merged`", "Dana unblocked it". Yours still say "You".
  - **Facts.** The Run section adds "started by michael · key `laptop`" under the agent tile. A **Credentials** section lists what this run used, by slot: `github` → "GitHub · michael · 1 use, 12:09".
  - **Blocked on a credential.** When a slot is empty, the ask is the ordinary blocked ask with one need, "Connect Linear for Triage an issue (`fetch_issue`)", and a **Connect Linear** pill beside it (the need's link); then **Resume the run**. Why: `credentials_missing`.
- **Reused.** All of `run.tsx`, `Beat`, `Facts`, `KV stacked`.
- **New.** The `credential` beat in its three forms, names instead of "You" for other members, two facts, the pill in a need.

## Navigation

The bar keeps its three parts. Left: the mark, "machine", and beside them the team's name as a quiet pill with a chevron. That one menu is the team switcher and the account: the teams you belong to (the current one marked with a Block), **Team** (members, invitations, agent keys, plan), **New team**, then a hairline, your email in ink-3, and **Sign out**. It shows for a team of one too, because Team and Sign out live in it. Centre: one Switch, **Runs · Machines · Credentials** (Runs keeps its red and amber counts). Right: nothing, except "■ Reconnecting…" as today. There is no sidebar, no profile page and no settings page; everything a person can change lives on Team or Credentials, and everything a machine needs lives in the editor.

## What stays out

Permissions beyond owner/member, personal credentials, approval before a use, audit pages (the run history is the audit), notifications, billing screens, SSO, describe-it in hosted v1 (it spawns local agents). Billing gets the one quiet "Plan" line and the reserved column until it exists.
